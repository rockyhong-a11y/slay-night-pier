# SLAY: NIGHT PIER

모바일 세로 화면용 SD 벨트스크롤 액션 게임. 야간 부두의 세 전투 구간을 돌파하는 **단일 스테이지**입니다.

- **아틀라스**: 파워밤 중심의 파워 타입. 적을 들어 올려 전방으로 내려꽂습니다.
- **노바**: 스플렉스 중심의 테크니션. 적을 붙잡고 후방으로 넘깁니다.
- 전투 중 두 주인공을 교대할 수 있으며 체력과 필살기 게이지는 각각 유지됩니다.
- **적 8명**: 바이퍼, 링스, 레이븐, 세라프, 템페스트, 엠버, 발키리, 최종 보스 오닉스.
- 세 전투 구간은 하나의 스테이지 안에서 이어집니다. 적을 정리하고 오른쪽으로 이동하면 다음 구간에 진입합니다.
- 3단 타격 콤보, 근접 잡기, 점프 킥, 광역 필살기, 적의 공격 예고, 점수와 최대 콤보 기록을 지원합니다.

**플레이:** https://rockyhong-a11y.github.io/slay-night-pier/

## 조작

| 행동 | 모바일 | 키보드 |
|---|---|---|
| 좌우 / 깊이 이동 | 왼쪽 조이스틱 | WASD / 방향키 |
| 타격 콤보 | 공격 버튼, 길게 누르기 | J |
| 파워밤 / 스플렉스 | 적 가까이에서 잡기 | K |
| 필살기 | 45 이상 게이지를 모아 필살기 | L |
| 점프 킥 | 점프 | Space |
| 파트너 교대 | 교대 | Q |
| 일시정지 | 상단 일시정지 | Escape |

공격하려면 적과 같은 깊이 선상에 서세요. 위아래 이동으로 위치를 맞출 수 있습니다. 쓰러진 파트너로는 교대할 수 없으며, 두 주인공이 모두 쓰러지면 게임 오버입니다. 여덟 명을 모두 제압하면 스테이지 클리어입니다.

## 실행

Node.js 22 이상을 사용하세요. 배포는 Node.js 24로 빌드합니다.

```sh
npm ci
npm run dev
npm test
npm run build
npm run preview
```

실제 브라우저 검증:

```sh
npx playwright install chromium
npm run dev
npm run qa
```

`PLAYWRIGHT_BROWSERS_PATH`와 `QA_URL` 환경 변수로 브라우저 설치 위치와 검증 URL을 지정할 수 있습니다. 검증 화면과 결과는 `artifacts/`에 생성됩니다.

## 아트와 모션

캐릭터 이름과 원본 SD 아트는 아래 저장소에서 가져왔습니다. 신규 캐릭터로 대체하지 않았습니다.

- https://github.com/rockyhong-a11y/slay
- https://github.com/rockyhong-a11y/slay-beach-volley

원본 전신 포즈와 방향별 달리기 프레임을 사용하고, **Blender 5.2.2 LTS**에서 파워밤 / 스플렉스의 두 캐릭터 궤적을 제작했습니다. 게임은 Blender에서 60Hz로 샘플링한 `public/assets/motion/grapples.json`을 사용합니다. 편집 가능한 Blender 파일과 재생성 스크립트는 `tools/`에 있습니다.

**Higgsfield**로 추가 파워밤 포즈를 생성하고, 원본 캐릭터와 맞는지 확인한 뒤 배경을 제거해 애니메이션에 사용합니다. 제작 상세와 원본 출처는 [ASSET_SOURCES.md](docs/ASSET_SOURCES.md)에 기록합니다.

베어너클 4와 캡콤 벨트스크롤 액션의 깊이 이동, 타격 콤보, 적 무리, 화면 진행을 참고했습니다. 해당 게임의 이미지나 음악은 포함하지 않습니다. 음악과 효과음은 Web Audio로 합성합니다.

## 모바일 인터랙션

비편집 UI의 텍스트 선택, 길게 누르기 메뉴, 이미지 드래그를 방지합니다. 조이스틱은 Pointer Events와 pointer capture로 동시에 이동과 공격을 지원합니다. 핀치 줌과 일반 화면 스크롤, 키보드 조작, 설정의 네이티브 체크박스를 유지합니다. 효과 줄이기 옵션과 시스템의 `prefers-reduced-motion`을 지원합니다.

## 배포

`main` 브랜치에 푸시하면 GitHub Actions가 테스트, Vite 빌드, GitHub Pages 배포를 실행합니다. 런타임 외부 서비스나 API 키가 필요하지 않습니다. 모든 에셋은 같은 저장소에서 제공합니다. 캐릭터 출처를 유지하며 본 저장소의 아트는 원본 저장소의 이용 조건을 따릅니다.
